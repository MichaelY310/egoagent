# 统一 Flow 观测与运行相簿

## 产品约定

Flow Graph 是执行结构的定义；Identity、模型、工具环境是它的运行绑定。
两个业务入口是当前项目 Chat 和标准 Task。Build 试跑、CLI、兼容 API 与子 Flow 也使用同一个执行器，不另造可视化专用 Agent loop。

在执行器的事件边界接入被动观察器：记录不可变图快照、运行来源、父子 Run、节点输入输出、模型/工具事件和结构变更。不由观察器改变执行状态。观察器故障不能使工具或模型调用重试。

原有 trajectory 仍是真实模型请求与训练导出的权威记录；观测库保存脱敏后的界面事件，不用截断的界面预览冒充完整训练数据。

## 实施与验收

1. 修复题库/历史互相阻塞、同步准备、配置回退、只读画布不测量等缺陷。
2. 用可索引的事件库取代观测时遍历全部历史文件；保留现有 Task 历史和训练轨迹。
3. 在 PipelineRunner 源事件处接入，所有入口与子图自动被发现。绑定来源 ID，界面可随时订阅，不需要提前打开观察面板。
4. 同一运行查看器用于实时观察和回放；显示实际图、当前节点、输入输出、工具、子运行和演进事件。
5. 添加录制/停止、保存完整运行到相簿、相簿打开回放、逐事件定位。回放只读，不重新调用工具或模型。
6. 图编辑事件与真正采用新图事件分开标识。保存到库不代表本轮已热替换。
7. 自动化覆盖源事件去重、子图归属、重启持久化、脱敏、分页、录制边界和被动故障隔离。浏览器验证 Chat 与 Task 两个入口。

## 环境边界

本地 Task 的独立工作目录不是 OS 沙箱；Docker Task 需要可用的 Docker engine，构建失败不得偷偷改为宿主执行。回放不需要 Docker 或 API Key。

## 用户操作

### 入口一：在当前项目里聊天

1. 在 IDE 打开你希望 Agent 处理的项目文件夹。
2. 在 Chat 的 Agent 配置选择 Flow、版本、Identity 和模式，然后发送消息。
3. 点击 Session 旁边的 **观察**。Build 会链接该 Session，保持只读，显示同一运行查看器。
4. 画布高亮实际执行节点；点击节点可查看截至当前事件的输入、输出、模型和工具事件。详情默认折叠。
5. 观察器没有执行控制权。继续输入、批准工具、停止运行仍在原 Chat 操作；退出链接后 Build 的试跑也不会控制 Chat。

### 入口二：选择题目并自动创建环境

1. 点击 Chat 顶部 **Workbench**，再点击顶部 **Evaluate**。
2. 宽面板从左侧题库选择题目；窄面板用顶部 **选择题目** 下拉框。**题库 / 导入 / 历史** 可展开完整列表与导入选项。
3. 选择 Runner、Harness、Flow version 和 Identity。Environment 勾选项是附加工具包；本地或容器后端由题目定义决定，界面会明确显示。
4. 第一次可选 **离线 DAG / Tool Trace 自检**，Harness 选 `aider_review_worker`，Identity 选 `test_bot`，不勾选额外 Environment。此题只跑固定脚本，不调用付费 API。
5. 勾选 **首节点前暂停**，点击 **开始做题**。准备阶段不再阻塞 HTTP；界面先显示“准备环境中”，进入执行器后显示图并暂停在 `input`。
6. 点击 **单步**：执行当前节点，暂停在下一个节点。点击 **自动**：继续执行。手动暂停的时间不计入执行超时预算。
7. 图下方 **评分** 查看四项确定性检查，**产物** 查看生成文件，**进化** 查看能力变更证据。点 **观察 / 回放** 可进入统一运行相簿。

Task 会创建 `.egoagent/task_runs/<run_id>/workspace`，不会把当前 IDE 项目作为题目写入目标。传入 IDE 附件时使用复制的上下文文件。Docker 不可用的题目会明确报错，不自动降级到宿主执行。

### 录制和相簿

1. 任何新运行自动写入底层观测库，不必先打开看板。
2. **开始录制**：从当前事件往后建立一个录制区间；**停止录制**：冻结区间。停止录制不会停止 Agent。
3. **保存完整运行到相簿**：保存从开始到当前时刻的全部已记录事件。Agent 以后产生的事件不会混入这份快照。
4. 点击顶部 **运行相簿**，选择“已保存的录制”下的卡片。点击 **播放**、**上一步 / 下一步**，或拖动 **回放事件位置** 滑块。也可以直接点底部时间线事件。
5. 用 **Agent / 子 Flow** 下拉框切换父/子执行；默认“跟随当前事件”。界面显示 workspace、Flow 版本/图摘要以及父节点。
6. 窄面板选择录制后自动收起列表，点 **相簿列表 / 切换运行** 可以再次选择。
7. 节点详情的 **结构变化 → 对应事件 → 修改前 / 修改后 → 在画布预览此版本** 可检查库中编辑。横幅明确提醒“不是当前执行图”；**返回实际执行图** 回到该事件真正采用的版本。

回放只展示事实，不重跑模型、工具或命令。录制不是屏幕视频；它是可逐事件浏览的结构化运行记录。

## 记录语义与工程实现

- `flow_observation.py`：SQLite/WAL 事件索引与不可变图快照。默认存储 `.egoagent/observations/observations.sqlite3`，可用 `EGOAGENT_OBSERVATION_DIR` 指定后端目录。迁移时应停服务后复制整个目录（包含可能尚未 checkpoint 的 WAL），不要只复制正在写入的单个数据库文件。
- `PipelineRunner / RunContext`：只在源事件处记录，子 Flow 转发给父 Flow 时不重复入库；无 UI 回调的 CLI/Python 调用也覆盖。
- Chat/Build、Task、兼容 API/SSE、durable run 标注来源；父子运行按根运行归组，Task 的多个 episode 也可以归在同一个题目记录下。
- 每个事件包含根运行、实际运行、节点、序号与实际图引用。图在运行开始及节点边界变化时保存；`harness_mutation` 的修改前/后另外存储。
- 保存库中 Flow **不等于**已经修改了执行器当前使用的图。只有真正采用后，主画布才随执行快照改变。本功能不引入新的任意时刻热替换机制。
- `FlowRunViewer.tsx` 是 Chat 链接观察、Task 和相簿共同的查看器；复用 Build 的节点布局、端口与边路由。它只读 API，不直接操纵执行器。
- 原始 `trajectory` 保存真实模型上下文/请求，继续用于训练导出；观测库用于脱敏的 UI 事件回放，部分节点值是有界预览，不能当作完整训练 payload。
- 观察器故障会记日志并停止该 Run 后续观测，但不能触发工具重试或改变 Agent 执行结果。磁盘不可写时不能保证录制完整，应检查后端日志。
- 原版外部 Codex CLI 没有 EgoAgent Flow，不伪造节点；仍通过其原生 JSONL 轨迹适配器查看。旧版未录制的运行保留原历史入口，不编造缺失事件。

API（沿用应用原有本地/远程鉴权边界）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/observations/runs` | 所有来源的根运行列表 |
| GET | `/api/observations/album` | 录制列表 |
| POST | `/api/observations/read` | 按 `root_id`、`after`、`limit`、可选 `recording_id` 分页读取 |
| POST | `/api/observations/record` | `start`、`stop`、`save`、`rename` |
